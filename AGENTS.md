# Agent Guide

For every new session or device, start at [docs/agent/README.md](docs/agent/README.md), then follow its workflow and handoff links to the Git-tracked active plan. These documents contain the shared delivery rules; do not depend on another machine's chat, private skills or absolute worktree paths. Fetch and reconcile remote state before executing a checkpoint. Push/merge to main triggers production deployment and requires the current batch's go-live approval.

Name branches by purpose using the repository convention: `feat/<topic>`, `fix/<topic>`, `docs/<topic>` or `chore/<topic>` in lowercase kebab-case. Never prefix branches with agent/tool names (for example `codex/` or `claude/`).

Read `package.json` and `package-lock.json` for current tooling; `README.md` owns setup and upgrade instructions.

- For sign-in/session changes, read `src/providers/AuthProvider.tsx`, `src/pages/LoginPage.tsx`, and their tests. Authentication does not accept trip invitations.
- For who may create accounts or the Google button, read `config/access.json`, `src/lib/accessConfig.ts` and `supabase/migrations/202610160003_new_account_access.sql`. The sign-up hook enforces the switch; a push alone does not apply it — follow the README runbook.
- For routing, read `src/App.tsx` and `src/components/AppShell.tsx`. The account key resets the workspace; the identity/trip key resets route forms. Preserve lazy loading and `src/components/PageErrorBoundary.tsx` recovery.
- For trip selection, queries or realtime, start at `src/providers/WorkspaceProvider.tsx`. It owns the single channel and identity/trip cache keys. Read adapters in `src/hooks/useWorkspace.ts` and writes in `src/hooks/useWorkspaceMutations.ts` must not add subscriptions. Late writes refresh their originating trip cache; only active-account UI may change selection.
- For website admin/co-owner changes, read the `site_admin_trip_co_owners` migration, `site_admin_co_owners_test.sql`, `GroupPage`, repository and provider tests. Admin is a private registry capability, never user metadata or an implicit membership/seat. Only the creator may demote co-owners; never demote the creator. Role writes use the trip-locked expected-role RPC; direct membership UPDATE is revoked. Admin content access must not turn non-members into payment recipients. Bootstrap only a privately approved verified account via the README runbook after go-live approval; never commit the real email/ID.
- For archive/restore, read `src/components/ArchiveTripControl.tsx`, `src/components/TripManager.tsx`, the `20261016131452_trip_archive.sql` migration and `trip_archive_test.sql`. Only owners may use the versioned RPC; archived contents remain hidden and all data/members/invitations are retained. Restore must work with no active trip. Preserve self-membership Realtime notifications, identity-scoped cache invalidation and the active-page invitation refresh (hidden invitees have no membership event). Apply the migration before the frontend.
- For persistence, read `src/services/travelRepository.ts` and `src/types.ts`; invitation/trip methods must match the SQL RPC signatures. Preserve legacy demo data when changing browser storage.
- For member names/checklists, start at `src/pages/GroupPage.tsx`, `src/components/DisplayNameForm.tsx` and `src/components/TripChecklist.tsx`. Names are self-managed and global; preserve account-wide workspace invalidation and email-local-part fallback.
- For checklist persistence, read the `names_and_checklist`, `authorize_checklist_validation` and `serialize_checklist_writes` forward migrations and `supabase/tests/database/names_checklist_test.sql`. Apply all before the matching frontend. Writes go through member-authorized RPCs with trip-before-item locking and version checks; direct API writes are revoked. Removal uses `deleted_at` for Realtime; membership removal clears assignments. Preserve legacy demo defaults.
- For expense splits, read `splitExpenseAmount`/`validateSplit` in `src/lib/expenseSettlement.ts`, `src/components/ExpenseForm.tsx`, the split columns in `src/lib/travelExcel.ts`, the `20261016220000_unequal_expense_splits.sql` migration and `unequal_split_test.sql`. Methods are equal (default), shares (leftover to a participating payer, else fixed order) and exact amounts that must total actual-or-estimate; deferred constraint triggers enforce this for every write. A null split method from an old client must not reset an unequal split.
- For itinerary times, read `src/lib/itineraryOverlap.ts`, `src/components/ItineraryForm.tsx`, `src/pages/ItineraryPage.tsx`, the `20261018000000_multi_day_itinerary.sql` migration and `multi_day_itinerary_test.sql`. A null `end_date` is a single-day activity (end time after start time); otherwise start time is on the first day, end time on the last, and the list shows it under every day. Overlap warnings never block saving and compare [start, end) intervals across days. `import_trip_data` keeps a stored `end_date` when an older client omits the key; Excel files without "Đến ngày" keep it too.
- For action messages, use `useNotify()` from `src/providers/NotificationProvider.tsx` (mounted per account in `src/App.tsx`) instead of inline feedback boxes; dialog form errors stay inline. Success toasts hide after 3 s (paused on hover/focus), errors stay until closed. History lives only in this browser's localStorage per account (newest 50, deletable from `NotificationBell`); never put secrets or other users' data in messages.
- For Excel report layout, `fitDataSheet` in `src/lib/travelExcel.ts` sizes columns from content and estimates wrapped row heights; write-excel-file 4.x styles text with `textColor` (a `color` key is ignored).
- For removing members, read `remove_trip_member`, `private.member_trip_balance` and `get_trip_former_people` in `20261016230000_settled_member_removal.sql` with `settled_member_removal_test.sql`. Removal requires a zero balance (mirrors `splitExpenseAmount`) and no estimate-only expense involving the member. Former members stay unchanged on old expenses (save RPC, `ExpenseForm`, Excel import) and cannot be added elsewhere; keep the SQL balance in step with the client split math. Expenses involving a former member have frozen money (A024): `20261016240000_lock_former_member_money.sql` triggers refuse amount/split/payer/participant changes and deletes (cascades excepted), mirrored by `involvesFormerMember` in the form, list, Excel and demo.
- For settlement payments, read `src/lib/expenseSettlement.ts`, `src/components/SettlementPanel.tsx`, the `20261016210500_settlement_payments.sql` migration and `settlement_payments_test.sql`. Only the recipient records ("payer paid me X") or undoes a payment; balances are expenses minus recorded payments, so later expense edits show the remaining difference. Writes use member-authorized RPCs with the trip lock and an expected count of all payment rows (undone rows included) that blocks duplicate records; undo is a `deleted_at` tombstone for Realtime. Apply the migration before the frontend.
- For invitations/capacity/multi-trip creation, read `supabase/migrations/202610140004_invitations_and_trips.sql` and `supabase/tests/database/`. Pending invitations reserve seats; owner revocation/recipient decline free them. Keep authorization and same-trip locking in the database.
- Add forward migrations; apply each missing migration once. Do not rerun historical migrations to restore a new database contract. Read the rollout note in `README.md` before deployment.
- Since `202610160004`, new database functions are not executable by default: grant EXECUTE to `authenticated` (never `anon`) for RPCs the app calls. Itinerary `maps_url` must stay an https Google Maps link, matching `isGoogleMapsUrl`.
- For membership consent, read `supabase/migrations/202610150001_require_membership_consent.sql` and `supabase/tests/database/membership_consent_test.sql`. Public API roles cannot insert memberships directly; preserve the authorized creation/acceptance RPCs.
- For release gates, read `.github/workflows/ci.yml`, `.github/workflows/deploy-pages.yml` and the delivery workflow in `README.md`. Pages must depend on shared verification; dependency auditing does not replace the security review. Keep release outcomes and remaining checks in `docs/releases/`.
- For calendar reminders/export, read `src/lib/tripReminder.ts` and its tests. Trip dates are inclusive; `.ics` end dates are exclusive. Banner/calendar export does not provide background push or email reminders.
- For focused checks, use `npx vitest run <test-file>`. Run `npm test`, `npm run lint`, and `npm run build` for integration. `npm run test:db:embedded` exercises unchanged migrations and pgTAP in ephemeral PostgreSQL; full Supabase tests (`npm run test:db`) are still needed for services/concurrent-session verification.

Do not edit generated `dist/`, dependency directories or ignored browser screenshots in `.artifacts/`. Never print private environment values or commit service-role credentials.
