# WanderPlan 0.8.0 — Recipient-confirmed settlement payments (R06)

In **Chi phí → Ai cần trả cho ai?**, the recipient of a suggested transfer taps **Đã nhận tiền** once they have been paid. The confirmation is stored as a payment record ("A đã trả B X đồng") and subtracted from balances, so the transfer disappears and any later expense change shows only the remaining difference. Payers and other members see "Chờ … xác nhận đã nhận". Only the recipient can undo a confirmation from **Đã thanh toán**; undone records stay in the database as history. Settled members show **Đã cân bằng**.

Customer rules (16/10/2026): only the recipient confirms/undoes; confirmations are payment records, recalculated when expenses change. Out of scope: payment processing, partial amounts, Excel import/export of payments, unequal splits (R10).

## Rollout and recovery

Apply only the additive migration `20261016210500_settlement_payments.sql` before deploying the frontend; it changes no existing rows. Never record payments in production as a deployment test. Prefer forward repair; an older frontend ignores the new table and shows unadjusted balances. Do not hard-delete payment rows.

Limits: hosted authenticated Realtime/email and a real Google OAuth round trip remain untested; production verification is read-only.
