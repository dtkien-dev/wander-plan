## Changes and diagnosis
Shared modal/form CSS bounds controls and nested grid items to their columns. Modal scrolling is vertical; native select overflow is contained at the field, with a visible outer focus ring. Date/time controls use the application's box styling and consistent edit/value sizing while retaining their original input types. Browser zoom, native select affordance, vertical scrolling and existing form/unsaved-edit behavior are preserved. No component, RPC, schema, access, data or dependency changes; package/lock/HTML0.18.1.

Reproduced on Windows WebKit with an80-character option label: the select's visible box fits, but overflow propagates into the modal. At viewport320, modal client/scroll widths were318/643;390:388/643;844:638/643. After repair they are318/318,388/388,638/638. Applying overflow only to the select did not fix this build; containment at its field did. This is evidence for a real overflow case, not proof of every cause on the customer's iPhone13.

Relevant upstream evidence: [WebKit301648](https://bugs.webkit.org/show_bug.cgi?id=301648) describes iOS date/time100%-width/padding behavior; [284644](https://bugs.webkit.org/show_bug.cgi?id=284644) and [299698](https://bugs.webkit.org/show_bug.cgi?id=299698) describe select intrinsic overflow. Native date/time box normalization also follows the established approach in [Bootstrap form controls](https://github.com/twbs/bootstrap/blob/main/scss/forms/_form-control.scss). No dependency on Bootstrap was added.
