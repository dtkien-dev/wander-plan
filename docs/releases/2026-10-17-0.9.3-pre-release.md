## Changes

- Excel money accepts safe whole numbers and text with consistent thousands groups (`1.234.567`, `1,234,567`, spaces or nonbreaking spaces). It rejects decimal/scientific-notation text, currency labels, booleans and unsafe integers instead of stripping arbitrary characters. Blank actual amounts remain null; typed numeric Excel cells still work.
- All repository collection reads paginate with exact counts and stable ordering. They advance by the actual number returned, so a server cap smaller than the requested 1,000 rows is supported. Later-page errors, missing/invalid counts, an unexpectedly empty page or a changed count reject the entire load rather than returning partial totals.
- Settlement rows include undone entries across all pages. Their complete row count remains the existing RPC duplicate-record guard; only active rows contribute to settlement balances.
- Workspace profile and people requests now run alongside the other independent collection requests after trip/session resolution. The normal small-trip load still has nine data requests, but no longer waits for collection completion before fetching profile and then people. No measured latency improvement is claimed.
- Demo expense/itinerary edits and deletions check the saved version and reject missing records. Expense deletion checks former-member involvement against the saved record.
- Vitest setup binds storage to jsdom's actual window, avoiding Node 25 native Web Storage overriding browser storage. No runtime dependency or production auth change.

## Scoped security review

Mode: separate local passes by the implementing agent, not an independent review. Scope: this diff and its callers, repository reads/writes, Excel preview/import, cache provider, affected SQL contracts and release workflows. Actors: signed-out users, members of another trip, current members and untrusted workbook authors.

Findings: no new verified vulnerability in the changed paths.

- Access control: collection pages retain trip filters, current credentials and existing database RLS/RPC checks. No privileged client, function grants, membership writes or authorization policy changes. Profile reads use the captured session identity; workspace caches remain account/trip scoped.
- Unsafe sinks/parsing: workbook amounts now fail validation on malformed input; archive size guards and Google Maps URL validation remain intact. No new HTML, command, URL-fetch or SQL interpolation sink.
- Business logic/API: payment count includes undone rows; database trip locks, expected-count checks and expense version checks remain authoritative. Partial page errors do not become a successful workspace. Demo stale writes are rejected; demo storage is not an authorization boundary or a cross-tab transaction.
- Platform/supply chain: no added dependency, credential, CI permission or deployment trigger. The shared verify-before-deploy workflow remains unchanged.
- AI/LLM: not applicable.

## Rollout and recovery

This change adds no migration and changes no RPC signature. The target database must already have the schema through `20261016240000_lock_former_member_money.sql` required by 0.9.2; verify migration history on the intended project before deploying. Do not replay historical migrations.

During original candidate preparation, no push/merge/tag/deployment was performed and GitHub CLI was unavailable in that environment. Production has since been deployed as verified above. Hosted email/OAuth delivery, concurrent multi-session Realtime behavior and mobile performance were not reverified during reconciliation.

Publication is complete; do not redeploy just to reconcile this note. Remaining post-deploy checks: valid/invalid Excel imports, multi-page totals/export, payment record/undo, trip switching and archive/restore with two authorized authenticated sessions. Record actual results separately from public metadata and local test evidence.

Recovery is a frontend rollback with no database rollback. Rolling back restores the older parser, truncation and stale-demo-write behavior; prefer a forward fix. Demo storage keys and legacy data remain unchanged.
